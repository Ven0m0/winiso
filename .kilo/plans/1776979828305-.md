### 6.4 Empty Catch Blocks

**Locations:**

- `win11_gaming_debloat.ps1` lines 44, 55, 62, 96, 114

**Action:** Replace `catch {}` with `catch { Write-Verbose "Ignored: $_" }` or remove try-catch entirely if safe. Since errors are non-fatal (script continues), consider using `-ErrorAction SilentlyContinue` on individual commands instead of wrapping in try-catch.

**Simplification opportunity:** Convert:
```powershell
try { dism /Image... | Out-Null } catch {}
```
to:
```powershell
dism /Image... /SomeFlags | Out-Null -ErrorAction SilentlyContinue
```
But check if `dism` errors need to be ignored. If yes, add `|| $true` or `-ErrorAction Continue` with `$ErrorActionPreference`.

**Recommendation:** Since these scripts are meant to be robust, keep try-catch but add comment explaining suppression: `catch { # Expected: package may not exist }`. Or remove empty catch if sufficient to let non-terminating errors pass (they do by default). Actually PowerShell non-terminating errors don't trigger catch unless `$ErrorActionPreference = 'Stop'`. The scripts set `$ErrorActionPreference = "Stop"` at top, making all errors terminating, so catches are needed. Keep but add minimal content: `catch { Write-Debug "DISM operation skipped: $_" }`.

But user instruction: "remove empty catch blocks". So either delete the try-catch entirely (if safe) or add minimal content. Since these are removing packages that may not exist, catch is necessary because `$ErrorActionPreference = "Stop"` would abort. So keep catch but fill with a comment or `Write-Verbose`. That is no longer empty technically. But to strictly follow "remove", we could drop the try-catch and use `-ErrorAction SilentlyContinue` on each DISM call. That's cleaner.

**Simplify:** Remove try-catch wrappers; add `-ErrorAction SilentlyContinue` to DISM commands that might fail (package removal). Example:
```powershell
dism /Image:$MountDir /Remove-ProvisionedAppxPackage /PackageName:"$p*" -ErrorAction SilentlyContinue | Out-Null
```
This eliminates empty catch blocks.

### 7.1 Edition Definitions — `convert_ve_plugin` vs `custom_convert.sh`

- `custom_convert.sh` lines 30-100 define an array `editions=( analogonecore ... serverdatacenternanocore )` — 78 items.

## Risks & Mitigations

- **Accidental deletion of config/scripts that are actually used:** Confirm each removal by cross-checking Makefile and build flow. When uncertain, favor keeping.
- **Breaking Windows compatibility:** Do not change CRLF on `.cmd` files.
- **PowerShell merge bugs:** Test logic paths manually (dry-run). Ensure both original use cases covered.
- **Indentation changes causing subtle bugs:** After re-indent, run `bash -n` on each script, `python -m py_compile` on Python files.
- **Removing catch blocks might abort on expected errors:** Ensure all suppressed errors are truly non-critical (package not found). Test conceptually: if package already absent, DISM returns non-zero; with `-ErrorAction SilentlyContinue` it continues.
